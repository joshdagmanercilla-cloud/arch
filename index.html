01 / ◇

Identity before secrets

Use workload identity federation and least-privilege roles. Keep credentials out of source, images, and static manifests.

02 / ⌁

Private by default

Place cluster workloads and stateful services on private network paths. Define controlled ingress, egress, and endpoint access.

03 / ◎

Trust the workload

Use service identity and encrypted service-to-service communication. Apply policy at both the network and application layers.

04 / ▧

Recover deliberately

Set backup retention, test restores, and make recovery objectives explicit for databases, object storage, and queued work.

05 / ◌

Observe the journey

Carry trace context across synchronous calls and messages. Alert on user-facing service objectives, not only infrastructure health.

06 / ⬡

Ship verifiable artifacts

Scan dependencies and images, restrict deployment permissions, and promote the same immutable artifact through environments.

02 / DESIGN NOTES

Built to be operated,
not just deployed.

A production-minded starting point. The best architecture is the one that fits the constraints of the people and systems around it.

Boundaries

Own the domain

Services should have clear responsibilities and data ownership. Avoid splitting services without a reason to do so.

Resilience

Expect partial failure

Use bounded retries, timeouts, idempotency, and dead-letter handling. Protect dependencies from cascading failures.

Operations

Make health visible

Pair resource requests and limits with service-level indicators, actionable alerts, and tested recovery procedures.
